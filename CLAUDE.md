# CLAUDE.md

Project instructions for Claude Code. Read this before making changes.

## What this is

The marketing site for **Neighborhood Cutz**, a barbershop at 3959 Wilshire Blvd #A23, Los Angeles. Built and maintained by North Code LLC for the client.

One page, six sections, no CMS. The single job of this site is to get a visitor to **book on Booksy or call the shop**. Every change should protect that path.

Booking is handled entirely by Booksy. This site never takes a payment, never stores a customer record, and has no backend. Keep it that way unless the client explicitly asks otherwise.

## Commands

```bash
npm install      # once
npm run dev      # http://localhost:3000
npm run build    # static export to ./out
npm run lint
```

There is no test suite. `npm run build` is the check that matters: it must pass before anything is pushed, because Netlify runs the same command and a broken build means the live site does not update.

## Stack

- **Next.js 15**, App Router, JavaScript (not TypeScript)
- **Static export** (`output: 'export'`), so the build emits plain HTML/CSS/JS into `./out` with no server. Netlify publishes that folder.
- **CSS Modules** per component, plus two global stylesheets
- **GSAP + ScrollTrigger** for the intro sequence and scroll reveals
- **Lenis** for smooth scrolling
- **Swiper** for the barbers and services sliders

All animation libraries are imported dynamically inside `useEffect` so they never reach the server bundle.

## Architecture

```
app/
  layout.jsx        fonts, metadata, JSON-LD business schema
  page.jsx          section order, nothing else
  globals.css       imports the two global stylesheets
components/         one .jsx + one .module.css per component
content/            ALL editable copy and business facts
hooks/              reusable client behaviour
lib/                pure functions, no React
styles/
  tokens.css        sizing engine + design tokens
  base.css          reset, type, shared utilities
public/images/      photos, served as-is
```

### The rule that matters most

**Content never gets hardcoded into a component.** Copy, prices, hours, barber names, phone numbers, URLs all live in `content/`. If you are about to type a business fact inside a `.jsx` file, stop and put it in `content/` instead, then read it from there.

This exists so the client can be handed a single folder to edit, and so a phone number change is one edit rather than six.

### Where styles go

- Used by **one** component → that component's `.module.css`
- Used by **three or more** components, or generated by a library at runtime → `styles/base.css`
- A colour, size, or spacing value → `styles/tokens.css` as a custom property

CSS Modules cannot scope attribute-only selectors like `[data-hero-bar]`. Those must live in `styles/base.css` or the build fails with "Selector is not pure". Two such rules already exist there and are labelled.

## Design system, do not break these

- **Everything is `em`, never `px`.** `styles/tokens.css` scales the root font size with the viewport, so the entire layout rescales proportionally from one place. A hardcoded `px` value breaks that and will look wrong at other widths.
- **Body text is uppercase** via `text-transform` on `body`. Write copy in normal sentence case in `content/`; the CSS handles the casing.
- **Display headings and body copy are justified.** That stretched word spacing is the defining choice of the design, not an accident. It reverts to left-aligned under 768px because justified type at narrow widths opens ugly rivers.
- **`mix-blend-mode: difference`** on the nav, corner markers and hero logo makes one white treatment readable over both the dark hero and the white page. Do not replace it with a colour swap.
- **Never put `overflow-x: hidden` on `html` or `body`.** Sliders bleed past the container on purpose; that bleed is clipped at section level by `.clip-x`, which uses `overflow-x: clip` specifically because it does not create a scroll container. Adding `hidden` higher up breaks sticky positioning and scroll anchoring.
- Any section containing a `<Slider>` must carry `className="clip-x"` or the page scrolls sideways.

## The intro animation

`components/Intro.jsx` runs the page-load sequence and drives elements it does not own, by data attribute:

| Attribute | Element |
|---|---|
| `data-page-content` | wrapper revealed at start |
| `data-hero-media` / `data-hero-media-inner` / `data-hero-fill` | the growing video frame |
| `data-hero-logo` | centre logo |
| `data-hero-bar` | bottom hero row |
| `data-hero-crop` | crop marks around the logo |
| `data-loader` / `data-loader-text` / `data-loader-bar` | the 0 to 100 counter |
| `data-navbar` / `data-menu-button` / `data-marker-overlay` | chrome that arrives last |

**If you rename or move any of these, update `Intro.jsx` in the same commit.** The page starts invisible, so a broken selector chain means a blank site. There is a 2 second failsafe that reveals the page if GSAP never loads; do not remove it.

## Accessibility and motion

Every change must hold this floor:

- `prefers-reduced-motion` is respected. `Intro.jsx`, `useSmoothScroll`, `useReveal` and `MobileMenu` all check it and skip animation. New animation must do the same.
- Visible keyboard focus, via the global `:focus-visible` rule.
- Tap targets stay at 44px minimum on mobile.
- Gallery and barber images use real `alt` text from `content/`, not filenames.

## Hydration

`useShopStatus` returns `null` on first render on purpose. The server and browser would otherwise disagree about the current time and React would throw a hydration mismatch. Any new time-dependent or random value must follow the same pattern: render a neutral placeholder, fill it in after mount.
